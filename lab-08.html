Troubleshoot and Debug Zero Trust Branch Environment

Use appliance console diagnostics to inspect interfaces, routes, VRRP, IPSec, and live ICMP traffic.

2 tasksOptional lab~20 minutesAssigned POD + Skytap
Lab objectives

What you will accomplish

  • Verify interface, routing, and neighbour state in the ZTB console.
  • Inspect gateway services, VRRP, and IPSec state.
  • Generate and observe bounded ICMP traffic on GE6.
Diagnostic approach

Work from link state to observed traffic

A useful troubleshooting sequence checks whether the interface exists and is up, whether the route is correct, whether the next-hop neighbour is reachable, and finally whether the appliance sees the packets. ZTB’s console also exposes containerized services used for routing/HA and secure tunnels. These commands are read-only diagnostics in the training environment; do not change container settings.

CheckQuestion answered
ip aIs the interface up, and what addresses are assigned?
ip routeWhich next-hop would the device use?
ip neighbourDoes it know the L2 neighbour/MAC for a next-hop?
docker ps, VRRP, IPsecAre service containers running and are HA/tunnel states healthy?
tcpdumpDo expected packets appear on the selected interface?
8.1

Inspect interfaces and routing

Confirm the basics of gateway addressing, routing, and local resolution.

Documented navigation: Zero Trust Branch → Deployments → Sites → [Site Name] → Console. Managing Sites ↗ · Using the Zero Trust Branch Debug Console ↗

Search menu → Sites / Console

If your interface differs, search for the feature rather than following older PDF screenshots.

  1. Navigate to your ZTB site, Zero Trust Branch → Deployments → Sites → [Site Name] → Console. Select the active appliance/console for your POD.
  2. Run ip a and identify the assigned IP addresses and operational state of GE interfaces.
  3. Run ip route to inspect gateway routes, default route, and nexthop selection.
  4. Run ip neighbour (or ip neighbor) and inspect IP-to-MAC mapping and neighbour state.
  5. Run cat /etc/airgap/zcc/fqdn.txt and verify that the source lab FQDN dcweb.ztwan.lab appears in the mapping output.
✓
Expected Result

The console displays interface addresses/routes/neighbours and the expected source-lab application hostname mapping.

8.2

Inspect gateway services and capture traffic

Use container status and bounded packet capture to isolate data-plane issues.

Documented navigation: Zero Trust Branch → Deployments → Sites → [Site Name] → Console. Using the Zero Trust Branch Debug Console ↗

Search menu → ZTB Debug Console

If your interface differs, search for the feature rather than following older PDF screenshots.

i
Bound packet captures

Always use a finite packet-count option such as -c 20. Zscaler documentation warns against unbounded tcpdump execution in the console.

  1. In the same console, run docker ps to list running services and identify the container names available in your image.
  2. Run the source-guide VRRP command docker exec vyos_container su - vyos sh -c "sudo /opt/vyatta/bin/vyatta-op-cmd-wrapper show vrrp" to inspect the active/standby state. If this command is unsupported on your appliance image, use the current commands documented by Zscaler for your console version.
  3. Run docker exec strongswan ipsec status to view IPSec connection and tunnel states in the source lab image. Container names/commands can vary by software version; do not interpret a missing container as proof of tunnel failure without checking version-specific documentation.
  4. In Skytap, open the Windows Server (Subnet10) VM.
  5. From Windows Command Prompt, generate continuous test traffic using ping 8.8.8.8 -t . Leave it running temporarily.
  6. Back in the ZTB Console, capture a bounded sample with tcpdump -i ge6 icmp -c 20 . Check for ICMP requests/replies on the GE6 interface associated with Subnet10. Stop Windows ping with Ctrl+C afterwards.
✓
Expected Result

The appropriate running services and protocol states are visible when present; the GE6 capture records the generated ICMP packets if traffic uses that path.
