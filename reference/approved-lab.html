Illustrative Configuration Lab

This example demonstrates how a finished hands-on lab should look: a clear goal, concise numbered actions, screenshots beside the relevant step, and a verifiable result for each task. It is not a real product configuration procedure.

Lab objectives

What you will accomplish

Introduce the learner to the configuration flow and show how each activity connects to a measurable goal. This description should use the available width rather than an artificially narrow column.

  • Recognize the lab topology and the purpose of the exercise.
  • Find the relevant feature using verified navigation or Search Menu.
  • Capture essential settings in a concise configuration table.
  • Verify the outcome before marking each task complete.
Technical context · Optional

Why the network foundation matters

A technical explainer should establish relationships and rationale before learners start clicking. It should help them understand why they are doing the lab without duplicating the numbered task instructions.

01 · Environment

Know what is connected

Identify the assigned lab systems and the relevant network boundaries.

02 · Configuration

Apply one logical change

Group related settings into a meaningful, learner-friendly task.

03 · Validation

Prove the result

Check the operational state or observed behavior rather than assuming the save succeeded.

1.1

Locate the feature

Demonstrate verified navigation and put the screenshot immediately after the step it explains.

  1. Open the assigned Zscaler administration portal using the lab-provided access details. Confirm you are working in the intended training environment.
    !
    Use the assigned lab environment

    Do not apply example configuration changes to a production tenant. Replace this warning with a course-specific caution when appropriate.

  2. Open the Search Menu and locate the feature named in the course instructions. Do not infer a current navigation path from an old source screenshot.
    Search menu → Course-specific feature keyword
  3. Confirm the feature's heading and available settings before continuing. When a navigation path has been verified, use the current path in the final guide.
✓
Expected result

The learner has reached the intended feature and confirmed that it belongs to the assigned lab environment.

1.3

Verify the expected outcome

Give the learner a clear, observable success condition.

  1. Return to the relevant status or configuration view and check that the saved object or setting is visible.
  2. Check the operational result specified in the real course guide. Where appropriate, include a screenshot immediately below this step showing the verified state.
  3. Mark the task complete only after the observed result agrees with the expected result.
✓
Expected result

The intended state or behavior is confirmed by observable evidence, not merely by the absence of a save error.
