Technical context · Network security

Macrosegmentation: controlling traffic between network groups

Why separate VLANs are not sufficient by themselves—and how ZTB firewall policy changes what can cross the boundary.

What is the security boundary?

In this lab, Subnet10 hosts the Windows server, Subnet20 hosts IoT, and Subnet30 hosts OT. Different VLANs separate broadcast domains, but routed communication can still be permitted between them. Macrosegmentation uses broad boundaries—subnets, VLANs or zones—to decide whether one group can reach another. ZTB evaluates traffic that passes through its gateway against the relevant firewall policies; simply creating VLANs is not the same as creating a deny rule.

How the Lab 2 policy proves enforcement

The first test establishes the baseline: Windows-to-IoT ICMP succeeds. You then add a Drop rule with source 10.1.10.0/24 and destination 10.1.20.0/24, commit it, and test again. The blocked ping and policy hit counter demonstrate that the route exists but the security decision changed. Next, Skip tells policy evaluation to move past this rule, so a subsequent applicable rule may permit the same traffic. Skip is not itself an Accept action.

Global versus site-specific intent

A global or template rule can provide a broad security baseline while site policy expresses a local exception. Policy order and scope determine which action wins; do not assume every site rule automatically overrides every global rule. In the final exercise, the OT-to-IoT test illustrates how policy placement and matching change the effective result.

2.2

Block Subnet10 to Subnet20 with macrosegmentation

Create a Drop policy, observe enforcement, then test the Skip action.

Documented navigation: Firewall → Policies (Global / Template / Site Policies). Zscaler Help Portal ↗

Search menu → Firewall Policies

If menu labels differ, use Search Menu. Source screenshots may show earlier navigation.

i
About ICMP flow reuse

The source notes that an existing ping flow may reuse an ICMP ID for up to five minutes. If results seem stale, stop the ping, wait, then retest.

  1. Open the assigned site and its Policies tab. Select Configure → Add Policy.
  2. Create a Drop policy using the required settings; select Add.
    SettingRequired value
    ActionDrop
    NamePOD##-Block-Subnet10-to-Subnet20
    Source ZoneLAN Zone
    Destination ZoneLAN Zone
    Source10.1.10.0/24
    Destination10.1.20.0/24
    PortsAll
    Time Schedule GroupMon-Fri-8-5 (optional in source)
  3. Select Commit; note that the policy hit count resets to zero.
  4. Return to the Windows Server, run ping 10.1.20.10 , and confirm packet loss.
  5. Edit the custom policy and change its Action to Skip. Save and Commit.
  6. Repeat the ping. Observe that traffic passes through the default allow rule, and compare the custom and default policy hit counts.
✓
Expected result

Drop blocks the Windows-to-IoT test; changing that same rule to Skip allows the default policy to handle traffic. The corresponding hit counts reflect the tests.

2.3

Allow OT-to-IoT at the site level

Demonstrate that a site-specific Accept rule can permit traffic otherwise blocked by a global rule.

Documented navigation: Firewall → Policies (Global / Template / Site Policies). Zscaler Help Portal ↗

Search menu → Firewall Policies

If menu labels differ, use Search Menu. Source screenshots may show earlier navigation.

  1. Open Firewall → Policies → Global Policies and review the preconfigured block for 10.1.30.0/24 to 10.1.20.0/24.
  2. From OT1 in Subnet30, run ping 10.1.20.10 and confirm the baseline traffic is blocked.
  3. Switch to Site Policies for your assigned site and select Configure → Add Policy.
  4. Create a site-specific Accept policy with these values.
    SettingRequired value
    ActionAccept
    NamePOD##-Allow-OT-to-IoT
    Source10.1.30.0/24
    Destination10.1.20.0/24
    PortsAll
  5. Select Add, then Commit. Retry the ping from OT1 and check that the site policy hit count increases.
✓
Expected result

OT1 can reach IoT through this site-specific exception, and its hit count increases; the preconfigured global rule remains present.
