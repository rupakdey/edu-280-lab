Validate Securing Internal and External Communication Policies

Test ZIA forwarding, private app connectivity and remote ZPA access from the lab endpoints.

4 tasksAssigned POD + SkytapSource guide · Lab 3
Lab objectives

What you will accomplish

  • Validate Windows Server Internet and private application reachability.
  • Authenticate ZCC, configure Internal DNS, and establish RDP via ZPA.
  • Optionally repeat security and reachability checks from IoT and OT.
3.1

Validate Windows server connectivity

Confirm Internet and private-application access from the Subnet10 Windows VM.

  1. Open the Skytap Server VM and visit http://ip.zscaler.com . Verify the Zscaler service location appears.
  2. Open Command Prompt and test ping 10.1.10.1 , ping 8.8.8.8 and ping cnn.com .
  3. Open http://www.888.com and observe the expected gambling-category restriction.
  4. Visit http://dcweb.ztwan.lab/ using the explicit http:// prefix, as required by this lab.
✓
Expected result

The Windows workload reaches the internet through Zscaler, receives the expected restricted-site response, and can open the private datacenter web service.

3.2

Access the Windows server remotely through ZPA

Authenticate ZCC, add the Internal DNS rule, and establish RDP to the branch server.

Documented navigation: Sites → your site → DNS Policies → Configure. Zscaler Help Portal ↗

Search menu → DNS Policies

If menu labels differ, use Search Menu. Source screenshots may show earlier navigation.

!
Session credentials and internal FQDN

Use your own POD identity. The RDP credentials in the source are administrator / Zscaler123! for this training environment; do not reuse them outside the assigned lab.

  1. Open the ZCC Lab Machine VM in Skytap and sign in using your assigned pod##-student@<FQDN> identity and session password.
  2. Confirm that Private Access and Internet Security show ON and ZCC is authenticated.
  3. Check basic connectivity: run ping 8.8.8.8 and ping cnn.com ; optionally visit ip.zscaler.com.
  4. Open your site’s DNS Policies → Configure → Add Policy. Create the Internal DNS redirect rule.
    SettingRequired value
    Rule NamePOD##-Internal-DNS-Policy
    SourcesLocal Interface IPs
    Destination domainpod##-winserver.ztwan.lab (replace ## with your POD digits)
    ActionRedirect
    DNS GatewayPrivate DNS Servers (10.73.50.20, 10.73.50.21)
  5. Select Add and Commit. Then resolve the assigned server name using ping pod##-winserver.ztwan.lab .
  6. Open Remote Desktop, connect to pod##-winserver.ztwan.lab, and use the Windows lab server administrator credentials supplied in the guide.
  7. After connecting, open Command Prompt and run ipconfig to inspect the remote server configuration.
  8. In Experience Center, locate Diagnostics using Search Menu and review the ZPA session, user, policy and application port.
✓
Expected result

The ZCC VM resolves the private Windows host through the configured DNS forwarders, connects with RDP through ZPA, and produces a visible diagnostic session.

3.3

Optional: Validate the IoT Ubuntu host

Confirm that the IoT subnet retains expected Internet/security behavior.

  1. Open the Skytap IoT VM (Subnet20).
  2. Visit ip.zscaler.com and cnn.com to verify service forwarding and Internet access.
  3. Try http://www.888.com to observe the expected gambling-category block.
  4. Run ping 10.1.10.10 to check access from IoT to the Windows Server.
✓
Expected result

The IoT host has the expected cloud/security behavior and its IoT-to-Windows communication remains permitted in this lab scenario.

3.4

Optional: Validate the OT Ubuntu host

Repeat the Internet, policy and inter-VLAN checks from Subnet30.

  1. Open OT1 in Skytap (Subnet30).
  2. Visit ip.zscaler.com and cnn.com to confirm Internet access through Zscaler.
  3. Try http://888.com/; the lab expects the gambling category to be blocked. If Chrome Safe Browsing interferes with the test, follow your instructor’s guidance.
  4. Run ping 10.1.10.10 to test OT-to-Windows reachability.
✓
Expected result

OT1 has Internet connectivity and the expected web controls, while the lab’s OT-to-Windows traffic is permitted.

✓
Lab 3 complete
