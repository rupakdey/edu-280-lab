Logs and Monitoring

Examine Packet Logs, Flow Logs, site alarms, and ZIA Web Insights for the assigned POD.

4 tasksOptional lab~15 minutesAssigned POD + Skytap
Lab objectives

What you will accomplish

  • Filter Packet and Flow Logs for your POD and inspect event details.
  • Examine Zero Trust Branch alarms and severity categories.
  • Run a location-scoped Web Insights log query.
Operational context

Why examine several kinds of logs?

Packets and sessions, platform alarms, and web transactions answer different questions. A traffic record helps establish whether a connection traversed the branch and what policy applied. Alarms signal operational conditions. Web Insights provides a view of web traffic processed through the Internet & SaaS service. Match each source to the question you are investigating; no single log proves every aspect of a request.

ViewUse it to investigate
Packet LogsTraffic/policy details and the individual matching records exposed by the portal
Flow LogsFlow/session-level traffic history over a selected time range
AlarmsAppliance/site health or other alert conditions by severity
Web InsightsWeb transactions associated with the assigned POD location
7.1

View packet logs

Filter ZTB traffic events for your POD and inspect a matching record.

Documented navigation: Logs → Insights → Packet Logs. Configuring SIEM Integration (packet/flow log paths) ↗ · Understanding Logging and Monitoring ↗

Search menu → Packet Logs

If your interface differs, search for the feature rather than following older PDF screenshots.

  1. Open Logs → Insights → Packet Logs in Experience Center. Use the calendar to select the last 3 hours and apply the timeframe.
  2. Add a filter: Field: Policy; Operator: is; Value: your assigned POD identifier, such as pod01 . Add the filter.
  3. Open any matching record with the detail/expand control. Review the fields in the table or JSON detail view; identify the applicable policy and traffic information shown.
✓
Expected Result

The Packet Logs view shows matching events for the selected window/POD; opening a record exposes useful traffic or policy fields.

7.2

View flow logs

Compare flow-level events to the packet-log evidence.

Documented navigation: Logs → Insights → Flow Logs. Configuring SIEM Integration (packet/flow log paths) ↗ · Understanding Logging and Monitoring ↗

Search menu → Flow Logs

If your interface differs, search for the feature rather than following older PDF screenshots.

i
Private/Incognito browser limitation

The source guide notes that third-party cookie restrictions in private/incognito mode can prevent Packet Logs and Flow Logs from loading. Use a normal browser session or adjust site cookie permissions if permitted by your lab policy.

  1. Open Logs → Insights → Flow Logs. Set the timeframe to last 3 hours and apply it.
  2. Add the same policy filter: Policy → is → your POD identifier, such as pod01 . Apply the filter.
  3. Open a matching flow entry and inspect its metadata; compare source/destination and policy with what you observed in Packet Logs.
✓
Expected Result

Flow Logs displays POD-scoped records and permits drill-down to detailed flow information.

7.3

Review Zero Trust Branch alarms

Inspect alert severity and determine whether warnings are present.

Navigation: Search Menu. Understanding Alarms and Notifications ↗

Search menu → Zero Trust Branch Alarms

The specific new-navigation breadcrumb could not be verified independently; the older source PDF path is noted in the steps for orientation.

  1. In Experience Center, search for Alarms under Zero Trust Branch. The source PDF uses the older path Administration → Alerts → Zero Trust Branch → Alarms. Open the alarms list for your assigned environment.
  2. Filter by Warning to inspect informational health or event conditions. Other supported severity options may include Emergency, Alert, Critical, Error, Notice, Informational, and Debug; available labels depend on the tenant.
  3. If no alarms appear, review the timeframe, severity selection, site/POD scope, and whether the environment currently has any matching conditions. An empty list alone is not a failure.
✓
Expected Result

The alarms view loads, severity filtering works, and matching warnings are visible if the environment has generated them.

7.4

Query POD web logs in Experience Center

Locate web activity associated with the assigned POD.

Documented navigation: Logs → Insights → Web Insights → Logs. About Insights (Web Insights path) ↗

Search menu → Web Insights

The source uses a User filter to select a POD location. Prefer a dedicated Location filter if that is how your current tenant lists the POD.

  1. Go to Logs → Insights → Web Insights, then choose the Logs tab.
  2. Click Add Filter and search for the User filter (as in the source guide).
  3. Choose the assigned POD location in the filter picker (for example pod01-student-location) and confirm your selection. The source screenshots use the User filter; if the location appears separately in the current interface, use the Location filter for the POD instead.
  4. Click Run Query; inspect the returned events and scroll horizontally to view additional columns.
  5. Optionally switch to Insights and apply the same appropriate POD/location scope to explore aggregate trends.
✓
Expected Result

Web Insights Logs returns matching web transactions when traffic is present in the chosen timeframe; filters reflect the intended POD scope.
